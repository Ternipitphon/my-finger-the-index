[ซอร์สที่ตรงกับตัวติดตั้ง](https://github.com/Ternipitphon/my-finger-the-index/releases/download/v0.8.21/Caprii-0.8.21-source.zip) · [รายละเอียดและ SHA-256](https://github.com/Ternipitphon/my-finger-the-index/releases/tag/v0.8.21) · [คู่มือภาษาไทย](https://github.com/Ternipitphon/my-finger-the-index/blob/caprii-0.8.21/caprii/CAPRII-TH.md)

**แก้ Spotify ชื่อยาว/หลายศิลปิน/ปุ่มไทย** ทดสอบกรณี “I Really Want to Stay at Your House” ที่มี Rosa Walton และ Hallie Coggins ปุ่ม “เล่นเพลง” ในการ์ดซ้อนหลายชั้นรองรับเพิ่ม ตรวจวิธี Invoke หรือ MSAA default action ของปุ่มที่ระบุชัดก่อนกดหนึ่งครั้ง หากยังไม่พบผลตรงและช่องค้นหามี plus/percent encoding ของคำค้นนี้พอดี จะแก้เป็นข้อความมีช่องว่างครั้งเดียวพร้อมตรวจ field/window/readback ไม่แก้ช่องอื่นหรือกรอกซ้ำเมื่อไม่แน่ใจ

เทียบชื่อแบบไม่ติดตัวพิมพ์/ช่องว่างและยังแยก Instrumental/1 HOUR ยืนยันศิลปินหลายคนจากผลที่เลือกและ Windows Playing สองครั้ง ไม่ใช้เพลง Magnolia ที่กำลังเล่นเป็นหลักฐานสำเร็จ การค้นในแอปยังต้องลองกับ Spotify รุ่นจริง ชุด Windows UIA ใช้หน้าจำลอง ไม่ใช่บัญชี Spotify ของผู้ใช้ อนิเมชันและวิธีดูจอเดิมคงอยู่

**ท่าทางประกอบงานจริง** ใช้ท่า curious/look และแยกร่างสั้นระหว่างคิด รอคำตอบหรือขออนุญาตใช้ท่าอยากรู้ งานเพลง/Agent ต้องมี verified จริงก่อนดีใจ งาน Agent ที่ผ่านและใช้เวลาตั้งแต่สองนาทีใช้ท่าฉลองเต็ม แค่เปิดเบราว์เซอร์หรือ AI เลือกเครื่องมือยังไม่ฉลอง ผลเก่าหลังปิดแชต/ยกเลิก/ปิดท่าจะไม่กระตุ้นอนิเมชัน ลดการเคลื่อนไหวตามตัวเลือกเดิม เปิด–ปิดได้ที่ ตัวละครและหน้าจอ → ลูกเล่นตัวละคร → ท่าทางประกอบงาน AI

**ดูจอคงสิทธิ์และสวิตช์เดิม** ท่าใหม่ไม่จับภาพ ไม่ส่งภาพ ไม่เรียก AI หรือสั่งงานเพิ่ม ไม่ให้สิทธิ์แทนผู้ใช้ เดโม มองดาวเทียม เข้าสิง หลับ/เก็บตัวและลูกเล่นเดิมยังอยู่ การเล่นเพลงที่ยืนยันใน 0.8.19 ใช้เส้นทางเดิม

**แก้ปุ่ม Play บนการ์ดผลค้นหา Spotify** รองรับปุ่มสีเขียวบนการ์ดผลบนสุดที่แยกจากแถวรายการเพลง เลือกเฉพาะการ์ดชื่อเพลงตรงและไม่ใช้ปุ่ม footer แทน ตรวจผล ลำดับและอายุหน้าต่างก่อนกดครั้งเดียว ไม่คลิกพิกัดหรือส่ง Space ถ้า Windows ยืนยันว่าเพลงและศิลปินที่เลือกกำลัง Playing อยู่สองครั้ง จะตอบว่าเล่นอยู่แล้วโดยไม่กดซ้ำ ทดสอบ UI Automation จริงบน Windows กับหน้าจำลองแบบรูปที่รายงาน ไม่ใช่บัญชี Spotify จริง ยังไม่ยืนยันเสียงลำโพง

**เล่นผลเพลงชื่อตรงบนสุดในแอป Spotify** สั่ง “เล่น weathergirl” โดยไม่ระบุศิลปิน เลือกผลเพลงตรงชื่อบนสุดตามลำดับบนจอ Spotify ถ้าระบุศิลปินให้กรองก่อน ชื่อซ้ำไม่ต้องถามกลับ ลำดับผลไม่ใช่หลักฐานยอดฟังหรือคุณภาพสูงสุด ระหว่างคุยเรื่องเพลงหรือเมื่อตอบคำถามอยากฟังเพลงอะไร พิมพ์ชื่อเปล่า ๆ ให้ AI ตีความเป็นเล่นชื่อเพลงนั้นได้ คำถามเกี่ยวกับเพลงยังไม่สั่งเล่น

อ่านผลและปุ่ม Play ผ่าน accessibility ตรวจลำดับ ผลและหน้าต่างก่อนกดครั้งเดียว ยืนยันชื่อเพลง ศิลปินของผลที่เลือก และ Windows Playing สองครั้ง ไม่ข้ามไปผลล่างเงียบ ๆ หากผลบนสุดไม่มีปุ่มใช้งาน ฟีเจอร์ค้นในแอปยังทดลองกับ Spotify แต่ละรุ่น ชุด CI ตรวจจำลองและ PowerShell ไม่ใช่บัญชีจริง ลอง Gemini จริงด้วยข้อความแต่งสามกรณีเฉพาะการตีความ ไม่ได้ควบคุมแอปหรือทดสอบเสียงลำโพง

**เล่นต่อ/หยุด/ข้ามผ่านแอป Spotify บน Windows โดยตรง** ใช้ Windows System Media Transport Controls เลือกเฉพาะ session ของ Spotify Store/desktop ไม่ผ่าน Chrome ไม่ส่ง Space หรือ media key ไปโปรแกรมอื่น ตรวจ PlaybackStatus และการเปลี่ยนเพลงจาก Windows จำตัวเล่น Windows/Chrome ที่ใช้จริงเพื่อให้คำสั่งต่อเนื่องไม่สลับไปผิดตัว ยังตรวจเสียงลำโพงไม่ได้ ถ้ายังไม่มี session จะลองเปิด Spotify หนึ่งครั้ง คำสั่งระบุเว็บ เพลย์ลิสต์ และ Liked Songs ยังใช้เส้นทางเว็บเดิม ปิดสวิตช์ Spotify Windows ในเมนู Chrome และเพลงเพื่อใช้เว็บสำหรับคำสั่งตัวเล่นได้

**แก้สถานะข้อความซ้ำ** ระหว่างรอใช้ข้อความสถานะเดียวแทนต่อบรรทัดเดิมซ้ำ แสดงเวอร์ชันในหัวแชต และแสดงสาเหตุเมื่ออ่านตัวเล่นผิดพลาดซ้ำ

**แก้ Spotify มีเพลงค้างแต่ Caprii อ่านว่าไม่มีเพลง** อ่านแถบตัวเล่นด้านล่างโดยไม่ต้องมี widget/control ID แบบเดิม ถ้าชื่อยังอ่านไม่ได้แต่มีเพลงโหลดและตำแหน่งเวลา ให้เล่นต่อจากตัวเล่นเดิมครั้งเดียว ไม่เปิดเพลง cache ทับ ไม่ใช้ชื่อจากการ์ดแนะนำ และตรวจเวลาเดิน/สถานะเสียงก่อนรายงาน

**จับคู่ Chrome ครั้งแรกครั้งเดียว** เปิดจำ Chrome หลังจับคู่กับ 0.8.13 ขึ้นไปแล้วปิด–เปิดแอปหรือ Chrome ใหม่จะเชื่อมกลับเอง กุญแจในแอปเก็บผ่าน Electron safeStorage แบบเข้ารหัส ตัวรับเริ่มพร้อมแอป ส่วนขยายลองเชื่อมกลับเมื่อแอปกลับมา ไม่ส่งงานเก่าซ้ำและไม่อ่านหน้าเองขณะเชื่อม มี Chrome และเพลง → ลืมการจับคู่ Chrome เพื่อเพิกถอนรหัสเดิม

**วิธีใช้ Spotify แบบแอป Windows:** ปิด Caprii จากถาดระบบแล้วติดตั้งรุ่นนี้ เปิดแอป Spotify และเล่นเพลงหนึ่งครั้ง จากนั้นหยุดไว้แล้วสั่ง “เล่นเพลงต่อ”, “หยุดเพลง”, “ข้ามเพลง” ผ่าน Caprii ได้ ไม่ต้องเชื่อม Chrome หรือ Reload ส่วนขยายสำหรับคำสั่งแอปเหล่านี้ การใช้เว็บยังใช้สิทธิ์/การจับคู่เดิมตามปกติ

**เพิ่มบริบทและตรวจความกำกวม** ใช้ URL/title ของแท็บ Chrome ที่อนุญาตแล้วโดยตัด query/fragment ไม่อ่านหน้าต่างหรือจับจอเพิ่มเอง ให้ AI ระบุผลลัพธ์ที่ต้องการ/ข้อมูลที่ขาดแบบสั้น หยุดเมื่อระบุว่าเป้าหมายกำกวม และอ้าง URL จากข้อความผู้ใช้ล่าสุดได้เมื่อเป็นคำขอต่อเนื่องชัดเจน เพิ่มเงื่อนไขแยกเปิดเว็บ เปิดแอป และโฟกัสหน้าต่างเดิม

[ดาวน์โหลดชุดทดลองฝึกโมเดลเจตนา](https://github.com/Ternipitphon/my-finger-the-index/releases/download/v0.8.21/Caprii-0.8.21-training.zip) — ฝึก CNN 8 route จากศูนย์บน CPU ด้วยข้อความแต่ง train 124/dev 18/test 42 ได้ 32/42 (76.19%) ยังไม่ใช้สั่งงานจริงและไม่ได้เปลี่ยนน้ำหนัก Gemini มี weights/scripts/data/รายงานข้อผิดครบ การ fine-tune โมเดลสำเร็จรูปยังไม่ได้รันเพราะสิทธิ์ดาวน์โหลด มี JSONL สำหรับ route-only เตรียมไว้โดยไม่อัปโหลดหรือเปิด paid job [วิธีรันและข้อจำกัด](https://github.com/Ternipitphon/my-finger-the-index/blob/caprii-0.8.21/caprii/training/intent/README-TH.md)

**แก้เปิด Spotify แล้วไม่ต่อถึงการเล่น** ใช้เส้นทางสื่อโดยตรง ไม่ถามยืนยันเปิดเว็บซ้ำ คำสั่ง “เปิดเพลง” และ “turn on some music” ให้ AI เลือกเล่นเพลงที่ค้างอยู่ ส่วนการเปิด Spotify อย่างเดียวใช้สวิตช์ autoplay จากแอปโดยตรง สั่งเล่นชัดเจนยังเล่นได้แม้ปิดสวิตช์ ต้องเชื่อม Chrome และล็อกอิน Spotify ไว้

**กวน ๆ ใช้ choom** พูดห้วน กระชับ เป็นกันเอง แซวได้โดยไม่ใช้คำลงท้ายทางการ ใช้คำเรียกเมื่อเข้าจังหวะไม่ยัดทุกประโยค กฎเดียวกันอยู่ในขั้นเรียบเรียงคำตอบใหม่ด้วย ไม่เติมในรหัส ตัวเลข โค้ด JSON หรือข้อความที่ต้องคงต้นฉบับ โหมดปกติ/เป็นห่วงยังเป็นตัวเลือกเดิม ค่าเริ่มต้นยังกวน ๆ

**แก้ขั้นเรียบเรียงคำตอบที่ติดตัวกรอง** ให้ AI แก้เฉพาะถ้อยคำในบริบทแยก ไม่ย้อนใช้บุคลิกกวนและประวัติชุดเดิม คำแซวสุภาพผ่านได้ตามเดิม รักษาเลข ลิงก์ และส่วนโค้ดที่มีเครื่องหมายกำกับ หากแก้แล้วเปลี่ยนข้อมูลสำคัญหรือยังไม่สุภาพจะไม่แสดง ไม่มีการเรียกเครื่องมือซ้ำจากขั้นนี้

**เมนูคลิกขวาจัดใหม่** คำสั่งคุย ดูจอ ย้ายตัวละคร และซ่อน/แสดงอยู่ด้านบน ที่เหลือแบ่งห้าหมวด: นิสัยและเสียง, Chrome และเพลง, AI และงาน, ตัวละครและหน้าจอ, ตั้งค่าและช่วยเหลือ เมนูหลักประมาณ 14 แถว เก็บฟังก์ชัน ค่าสวิตช์ และทางลัดเดิมครบ

[ดูภาพตัวอย่างเมนูจริงจากการทดสอบบน Windows](https://github.com/Ternipitphon/my-finger-the-index/releases/download/v0.8.21/Caprii-0.8.21-menu.png)

**AI เลือกตอบหรือเรียกเครื่องมือในรอบเดียว** แชตทั่วไปได้คำตอบสุดท้ายจากรอบตัดสินใจ ไม่แยกประเภทแล้วเรียก AI ตอบซ้ำ ส่งประวัติคุยแบบจำกัดและความจำที่เปิดบันทึกไว้ พร้อมนิสัย ภาษา และความยาวคำตอบ คำสั่งใช้เครื่องมือจริงแล้วตรวจผลก่อนตอบ คำขอดูจออย่างเดียวจับภาพจริงตามสิทธิ์เดิมก่อนวิเคราะห์ ไม่แต่งว่าทำงานแล้วจากข้อความของโมเดล งานหลายขั้นตอน การวิเคราะห์ภาพ โมเดลสำรอง หรือการแก้ถ้อยคำยังอาจต้องเรียก AI เพิ่มตามความจำเป็น โหมด Claude Code ใช้ Agent เดิม

เมื่อสั่งเปิด Spotify หรือเปิดเพลงล่าสุด ระบบรอเพลงที่ค้างอยู่ในตัวเล่นแล้วเล่นต่อก่อน ไม่ใช้เพลงใน cache ทับเพลงที่ผู้ใช้เปิดเอง ถ้าตัวเล่นไม่มีเพลงจึงใช้เพลงที่ Caprii เคยตรวจไว้ พร้อมตรวจเวลาเดินและเสียงแท็บ ต้องเข้าสู่ระบบและเชื่อมส่วนขยาย Chrome เมนูเล่นอัตโนมัติยังเปิด/ปิดได้

คลิกขวา Caprii → **นิสัยและเสียง → นิสัย** เลือก **กวน ๆ / เป็นห่วง / ปกติ** กวน ๆ แซวสิ่งที่เห็นหรือสถานการณ์แบบเป็นมิตร ลดคำห่วงและคำเตือนที่ไม่เกี่ยวข้อง เป็นห่วงเน้นอบอุ่นใส่ใจ ทุกแบบยังเป็น Caprii และตอบข้อมูลจริง ใช้กับแชต ดูจอ และภาพแนบ จำค่าไว้เมื่อเปิดใหม่ ค่าเริ่มต้นยังกวน ๆ และคงตัวเลือกเดิมของผู้ใช้ ไม่เปิดดูจอหรือไมค์เพิ่มจากการเปลี่ยนนิสัย

ตัวอย่างคำขอเพลง: “เล่นเพลงที่ผมกดชอบหน่อย”, “Play my liked songs” และ “Could you play my Night Drive playlist?” รับไทย/อังกฤษได้ทั้งสองโหมด English เป็นภาษาหลักเมนูและคำตอบ ระบบเล่นและตรวจผลเดิมยังทำงานต่อ การเปิดเว็บ Spotify อย่างเดียวคงสวิตช์ autoplay เดิม

## Caprii 0.7.6 — Spotify เปิดใหม่และเล่นอัตโนมัติ

แก้ช่วงรอแท็บใหม่ไม่ให้ติดล็อกว่างานกำลังทำอยู่ รอเอกสาร Spotify โหลดครบและใช้ session ใหม่ก่อนเล่น ไม่ส่งคำสั่งอัตโนมัติไปแท็บเก่าที่ไม่ได้ใช้งาน รองรับลิงก์ /intl-th/ และ /intl-en/ อ่านปุ่มและเอกสารใหม่ทุกครั้ง

เมนูคลิกขวา → **เล่นเพลงอัตโนมัติเมื่อเปิด Spotify** เปิดเป็นค่าเริ่มต้นตามคำขอผู้ใช้ เมื่อสั่ง “เปิด Spotify” จะเล่นเพลงล่าสุดที่เคยตรวจได้ มีสวิตช์ปิดเป็นเปิดเว็บอย่างเดียว บันทึกเฉพาะชื่อ ศิลปิน และ public track URL ในเครื่อง ถ้ายังไม่มีเพลงล่าสุดในเว็บ/แอป ให้สั่งชื่อเพลงหรือ Liked Songs ครั้งแรกก่อน ไม่เลือกเพลงสุ่มแทน

หลังเปิด Spotify สั่ง “หยุดเพลง”, “ข้ามเพลง”, “เพลงก่อนหน้า” และ “เล่นต่อ” ได้ผ่านปุ่ม Spotify โดยตรง ตรวจว่าเวลาหยุดหรือเพลงเปลี่ยนแล้ว ไม่รายงานจากการกดปุ่มอย่างเดียว

แยกเวลาเพลงเดินกับ Chrome รายงานเสียง ตรวจแท็บปิดเสียง อุปกรณ์ที่กำลังเล่น และเอกสารที่เปลี่ยน ถ้าสถานะที่กู้คืนบอกว่าเล่นอยู่แต่ไม่มีเสียง จะลองเปิดเพลงเดิมใหม่หนึ่งครั้ง ไม่วนกด หากพบอุปกรณ์อื่นจะเลือกเฉพาะตัวเลือก This web browser ที่ระบุชัด ถ้าระบุไม่ได้จะแจ้งให้เลือกเอง ไม่เปลี่ยนไปอุปกรณ์อื่น การรายงานเสียงของ Chrome ยังไม่ยืนยันเสียงลำโพงหรือ Volume Mixer และ Chrome อาจต้องให้กด Play เองครั้งแรก

**อัปเดตทั้งแอปและส่วนขยาย 0.7.6:** ปิดแอปเก่าจากถาดระบบ ติดตั้งใหม่ แล้วกด Reload ส่วนขยายใน chrome://extensions เชื่อมใหม่ด้วยรหัสรอบนี้และเปิดโหมดจำ Chrome หากต้องการปิดแท็บแล้วเปิดใหม่โดยไม่ใส่รหัสซ้ำ

## Caprii 0.7.5 — ปุ่มคุยอยู่นิ่ง ไม่ตอบสนอง

หยุดแอนิเมชันไล่ข้อความระหว่างกด เพราะการขึ้นบรรทัดใหม่ทำให้ตัวปุ่มขยับภายในกล่องได้ พร้อมแก้การปลดล็อกพื้นที่คลิกเมื่อไม่มี DOM mouseup ใช้เมนูคลิกขวา → คุย เป็นทางสำรองได้ตามเดิม

โหมดนี้เป็นตัวเลือก ต้องยอมรับสิทธิ์เว็บไซต์ใน Chrome ก่อน ควบคุมแท็บปัจจุบันครั้งละหนึ่งแท็บ ไม่อ่านทุกแท็บหรือฉีด DOM script เพียงเพราะสลับแท็บ ไม่ติดตามหน้าลับหรือ chrome:// และไม่ย้ายงานที่กำลังทำไปแท็บอื่น กด **ตัดการเชื่อมต่อ** เพื่อลบรหัสที่จำไว้และถอนสิทธิ์เว็บไซต์ หากปิด–เปิดแอป Caprii ใหม่ต้องเชื่อมรหัสใหม่หนึ่งครั้ง

อัปเดตแอปและส่วนขยายเป็น 0.7.3: ปิดแอปเก่าจากถาดระบบ ติดตั้งใหม่ กด Reload ส่วนขยายใน chrome://extensions เปิด Spotify ที่ล็อกอิน แล้วเปิด popup ติ๊กโหมดจำ Chrome และอนุญาตสิทธิ์ เมื่อเชื่อมแล้วสั่ง “เล่นเพลงใน Liked Songs”

## Caprii 0.7.1 — เชื่อมแล้วแต่แอปยังบอกว่าไม่ได้เชื่อม

ส่งคำสั่งผ่าน extension worker แทน page timers ที่อาจถูก Chrome ชะลอในแท็บเบื้องหลัง โหลด DOM bridge เมื่อจำเป็นและคืนการทำงานหลังเครือข่ายสะดุด ไม่ส่งคำสั่งที่รับไปทำแล้วซ้ำเมื่อ ack หาย ยังควบคุมเฉพาะแท็บและ origin ที่ผู้ใช้เลือก ไม่เพิ่มสิทธิ์ส่วนขยาย

**อัปเดตทั้งแอปและส่วนขยายเป็น 0.7.1:** ปิด Caprii จากถาดระบบก่อนติดตั้ง เปิดโฟลเดอร์ส่วนขยายจากแอปใหม่และกด Reload ใน chrome://extensions จากนั้นเปิดแท็บ Spotify ที่ล็อกอินแล้ว เชื่อมใหม่ด้วยรหัสของรอบนี้ครั้งเดียว แล้วพิมพ์ “เล่นเลย” การพักแท็บอย่างเดียวไม่ต้องกดเชื่อมใหม่ทุกคำสั่ง

เมื่ออยู่หน้า Liked Songs ที่ต้องการอยู่แล้วจะไม่โหลดหน้าใหม่ และการกด Play ไม่รอตัวจับเวลาในหน้าเว็บ การเปิดหน้าตัวเล่นเป็นคนละขั้นกับการยืนยันเพลงเล่น จึงยังตรวจสถานะและเวลาเดินตามเดิม หากเชื่อมผิดแท็บจะบอกชื่อเว็บไซต์ที่เชื่อมอยู่ ถ้ารุ่นส่วนขยายไม่ตรงจะแจ้งให้อัปเดตตรงจุด

- `เปิดyoutubeแล้วก็ค้นหาว่าlimbus` เปิด URL หน้าผลค้นหาโดยตรง ไม่ใช้ LLM เดาลิงก์และไม่เปิดคลิปแรกเอง
- `เปิด spotifyแล้วกดเล่นเพลงในliked song` เปิด Liked Songs ในแท็บ Spotify ที่เชื่อม แล้วกดเล่นและตรวจเวลาเพลงเดิน
- `เปิดเพลงชื่อ Harpy Hare ของ Yaelokre ใน Spotify` ค้นหาและเลือกชื่อ/ศิลปินตรงกัน ถ้าชื่อและศิลปินเดียวกันซ้ำหลายชุด ใช้ผลตรงอันดับสูงสุดของ Spotify; ถ้าคนละศิลปินจะถามเพิ่ม
- `เล่นเพลย์ลิสต์ Night Drive` ใช้ลิงก์ในคลังที่อ่านได้; `เล่นเพลงใน playlist นี้` ใช้เพลย์ลิสต์ที่เปิดในแท็บปัจจุบัน ถ้าระบุไม่ได้จะถามชื่อหรือลิงก์
- `เล่นเลย` ทำคำสั่ง Spotify รอบล่าสุดต่อในบทสนทนานี้ได้ ไม่ต้องพิมพ์รายละเอียดซ้ำ หลังเปลี่ยนไปทำงานอื่นจะไม่ย้อนมาเล่นเพลงเก่า

**ตั้งค่า Spotify ครั้งแรก:** ติดตั้ง 0.7.1 แล้วเปิดโฟลเดอร์ส่วนขยายจากเมนู Caprii และรีโหลด/ติดตั้งส่วนขยาย 0.7.1 ใน Chrome เปิด Spotify Web Player ล็อกอินด้วยตัวเอง และอนุญาตให้ Caprii ใช้แท็บนั้น ถ้ายังไม่เชื่อม แอปจะเปิดหน้าที่ต้องการและบอกว่ายังไม่ได้เล่น จากนั้นเชื่อมแท็บแล้วพิมพ์ “เล่นเลย” การค้นหา YouTube ไม่ต้องเชื่อมแท็บ

Spotify ใช้การควบคุม Web Player ไม่ใช้รหัสผ่าน คุกกี้ OAuth token หรือ Spotify API จากบัญชีผู้ใช้ ไม่มีการซื้อ Premium แก้เพลย์ลิสต์ กด Like หรือเปลี่ยนอุปกรณ์เล่นอัตโนมัติ การเล่นยังขึ้นกับสิทธิ์บัญชีและนโยบาย autoplay ของเบราว์เซอร์ อาจต้องกด Play ครั้งแรกในเว็บด้วยตัวเอง หากกดแล้วเวลาไม่เดินจะรายงานว่ายังยืนยันไม่ได้ ไม่มีการกด Play ซ้ำอัตโนมัติ Ctrl+Alt+Esc หยุดขั้นตอนที่เหลือ ส่วนเพลงที่เริ่มแล้วควบคุมจาก Spotify

ส่วนขยายคง session เมื่อย้ายหน้าในเว็บไซต์เดิมที่ผู้ใช้เชื่อม และตัดการเชื่อมต่อเมื่อออกคนละ origin เช่นหน้าเข้าสู่ระบบ ไม่เพิ่มสิทธิ์นอก activeTab/scripting/storage ทดสอบด้วย DOM จำลอง ไม่ใช่บัญชี Spotify หรือเสียงจริง

## Caprii 0.7.1 — ลากได้ช่วงแรกแล้วหยุดทำงาน

เพิ่มการอ่านสถานะปุ่มเมาส์หลักจริงผ่าน Windows helper เดิม (รองรับการสลับปุ่มสำหรับผู้ใช้ถนัดซ้าย) เพื่อใช้ประกอบการจบการลาก ไม่อาศัย pointerup/mouseup เพียงอย่างเดียว ถ้าข้อมูลปุ่มเก่าหรือ helper ไม่พร้อมจะถือว่ายังไม่ทราบสถานะ ไม่ตีความว่าได้ปล่อยปุ่มแล้วโดยอัตโนมัติ

เมื่อจับตัวละครจะยกเลิกเส้นทางเดินเล่นเก่าและเลื่อนการเดินอัตโนมัติออกไป ระหว่างกดค้างจะพักการเดินเล่นก่อนเริ่มลาก ทิ้งตัวอย่างเคอร์เซอร์ที่ตอบช้าจากการจับครั้งก่อน และตรวจการปล่อยปุ่มจริงแม้ไม่มีเหตุการณ์จากหน้าต่าง ทางย้ายสำรอง Ctrl+Alt+M ยังคงใช้ได้ ข้อมูลปุ่มอยู่ในเครื่อง ไม่เก็บลงดิสก์หรือส่งให้ AI

ทดสอบ sprite ลาก–ปล่อย 30 รอบต่อเนื่อง (แอนิเมชันน้อย 15 + เต็ม 15 รอบ) ด้วยสถานะปุ่มจำลอง รวมเหตุการณ์ปล่อยที่มาเร็วและเหตุการณ์ปล่อยที่หายไป ผ่าน 186 app tests แต่ยังไม่ได้ยืนยัน Windows helper และการจับจริงบน Windows

## Caprii 0.7.1 — คลิกติดแต่ลากไม่ขยับ

แก้การลากที่ได้รับ mousemove แต่ไม่มี pointermove รองรับทั้ง MouseEvent และ PointerEvent ไม่ปล่อยตัวละครเพียงเพราะหน้าต่างเสียโฟกัสหรือ mouse pointer capture หลุด และอ่านตำแหน่งเคอร์เซอร์โดยตรงทุกประมาณ 32 ms เฉพาะตอนกำลังจับ ล็อก native click-through ตลอดการจับ ไม่ให้การตรวจ hit/rearm สลับหน้าต่างเป็นคลิกทะลุระหว่างลาก

หากลากโดยตรงยังมีปัญหา: คลิกขวา **ไอคอน Caprii ในถาดระบบข้างนาฬิกา** → **จับย้ายตัวละคร — ขยับเมาส์แล้วคลิกวาง** หรือ **Ctrl+Alt+M** ไม่ต้องกดค้าง คลิกซ้ายเพื่อวางหรือคลิกขวา/Ctrl+Alt+Esc เพื่อยกเลิก เลือกได้เฉพาะหน้าจอที่ตัวละครอยู่ มี timeout 30 วินาทีเพื่อไม่ให้ติดโหมดจับ


## Caprii 0.7.1 — ลากตัวละคร ดูจอ และภาษาอังกฤษ

- จับลากตัวละครได้ระหว่างแอนิเมชัน โดยใช้ pointer capture และปล่อยได้เมื่อเมาส์ออกนอกตัวละคร ยกเลิกการปฏิเสธการจับ

- คลิกขวา → **ภาษา / Language** → **English — primary language** เปลี่ยนภาษาบทสนทนา เมนูที่รองรับ และบทพูดดูจอ บันทึกข้ามการเปิดแอป ค่าเริ่มต้นยังเป็นไทย บางข้อความวินิจฉัยเครื่องมือยังเป็นไทย
- เปิดอ่านบทพูดด้วยเสียงได้ ใช้เสียงระบบที่ตรงกับภาษาหลักเท่านั้น ถ้าไม่มีเสียงภาษานั้นจะไม่อ่านแทนด้วยภาษาอื่น

## ตั้งค่าคำตอบที่ยังคงรองรับ

- **คลิกขวา Caprii → ความยาวคำตอบ / คำพูด** เลือก **สรุปสั้น (1–3 ประโยค)**, **สมดุล**, หรือ **ละเอียด** ค่าเริ่มต้นสรุปสั้นทั้งโปรไฟล์ใหม่และเดิม และจำค่าหลังปิด–เปิดแอป
- ใช้กับแชต การดูหน้าจอ การอ่านรูปแนบ และสรุปตอนจบของ Agent เอาคำตอบหลักขึ้นก่อน ลดคำเกริ่น/มุกซ้ำ ไม่ตัดข้อความกลางประโยคหรือย่อ JSON/โค้ดของเครื่องมือ
- ขอ “อธิบายละเอียดทีละขั้นตอน” หรือ “ขอสั้น ๆ” สำหรับรอบนั้นได้ โดยไม่เปลี่ยนค่าหลัก ความยาวเป็นคำแนะนำให้โมเดล ไม่ใช่การตัดคำตอบด้วยจำนวนตัวอักษรตายตัว
- คำถามอย่าง **“ข้อนี้ตอบอะไร”**, **“อันนี้ตอบอะไร”**, **“ช่วยตอบข้อนี้หน่อย”** จะขออ่านโจทย์จริงจากแท็บที่เชื่อมหรือภาพหน้าจอหลังอนุญาต ตรวจคำตอบด้วยเครื่องมือเมื่อเป็นตัวเลข แล้วตอบโดย **ไม่กรอก/ไม่กดส่ง** ถ้าห้ามอ่านจอจะไม่เริ่มสังเกตจอ
- แก้ข้อความเชื่อม Chrome ให้แยกแอปไม่พร้อม รหัส/รุ่นส่วนขยายไม่ตรง session หมดอายุ และหน้า `file://` ชัดขึ้น พร้อมล้างสถานะเชื่อมต่อหากฉีด DOM script ไม่สำเร็จ
- เพิ่มคำสั่งให้ยึดข้อมูลที่เห็นจริง ไม่เดาตัวเลข ไม่โทษผู้ใช้ และไม่ถามหารูปซ้ำทั้งที่มีภาพแนบจริง ไม่เปลี่ยนโมเดลเป็นรุ่นแพงขึ้นอัตโนมัติ

ทดสอบ Gemini 3.5 Flash Lite ด้วยรูปสังเคราะห์จริง: ตอบจำนวนกล่องสีแดงได้ถูกต้องใน **54 ตัวอักษร** ด้วยค่าเริ่มต้นสรุปสั้น

## บุคลิกและรูปภาพที่ยังคงรองรับ

- **บุคลิกเปิดเป็นค่าเริ่มต้น** ทั้งโปรไฟล์ใหม่และเดิม: พูดตรง มั่นใจ ขี้แซวแบบเป็นมิตรและห่วงผู้ใช้ ได้แรงบันดาลใจจากรีเบคก้า ปิดได้ที่เมนู “บุคลิกกวน ๆ แบบรีเบคก้า” ไม่ใช่ตัวละครจริงหรือผลงานทางการ บุคลิกไม่แทนที่ข้อเท็จจริงหรือการอนุญาตเครื่องมือ
- **ปุ่ม 📎 แนบรูปในแชต** เลือก PNG/JPEG/WebP หรือคัดลอกรูปแล้ววางด้วย **Ctrl+V** มีตัวอย่างก่อนส่ง ลบรูปออกได้ ใส่คำถามหรือส่งเฉพาะรูปก็ได้
- วิเคราะห์รูปที่แนบจริง **แยกจากการดูหน้าจอ** ส่งพิกเซลให้ provider/model ที่เลือกเมื่อกดส่ง ไม่บันทึกพิกเซลลงประวัติแชต ไฟล์ไม่เกิน 15 MB / 40 ล้านพิกเซล และย่อด้านยาวไม่เกิน 1600 px
- โมเดลที่ไม่รองรับภาพจะแจ้งและเก็บรูปให้เปลี่ยนโมเดล/ลองใหม่ ไม่แอบเปลี่ยนเป็นคำตอบข้อความล้วน ช่องนี้ยังไม่รองรับ Claude Code mode ใช้ Gemini หรือโมเดล vision ที่รองรับแทน
- ทดสอบ Gemini 3.5 Flash Lite ด้วย PNG สังเคราะห์จริงแล้ว นับกล่องสีแดง 3 กล่องได้ถูกต้อง โดยเปิดบุคลิกใหม่ ไม่ได้ใช้รูปส่วนตัว
- Test Lab เพิ่มเคสอ่านรหัสจากภาพเป็น **8 เคส** เว็บตรวจรหัสที่กรอก ไม่ให้คะแนนบุคลิกหรือยืนยันด้วยตัวเองว่า AI เป็นผู้ลงมือ

| ตรวจค่าหลังกรอก | อ่านค่าจริงกลับจากช่อง ไม่ถือว่าการส่งคำสั่งพิมพ์เท่ากับกรอกสำเร็จ |
| ตรวจผลหลังส่ง | รอผลแบบกำหนดเวลาและตรวจเฉพาะส่วนผลลัพธ์ ไม่ใช้ข้อความสำเร็จที่มีอยู่ก่อนคลิกส่งมายืนยันรอบใหม่ |
| หน้าเว็บเปลี่ยน | ปฏิเสธ ID/generation เก่า ช่องที่ถูกแทนที่ ซ่อน หรือเปลี่ยนตัวเลือก เพื่อให้อ่าน DOM ใหม่ก่อนทำต่อ |
| ทำตามข้อจำกัด | คำสั่งใหม่เคารพ “ห้ามกรอก” และไม่ส่งคำสั่งซ้ำเมื่อผลก่อนหน้ายังไม่แน่ชัด |
| Test Lab ในแอป | เปิดเว็บทดสอบในเครื่องจากเมนู Caprii ได้เลย ไม่ต้องเปิด server หรือใช้ Node.js แยก |
| ชุดติดตั้งรุ่นใหม่ | แอปและส่วนขยาย Chrome เป็น 0.7.3 พร้อมแพ็กเกจ part และการตรวจ SHA256 ตามรูปแบบรุ่นก่อน |

การกรอกผ่าน DOM ใช้ได้กับ browser ของแอปและแท็บ Chrome ที่ผู้ใช้เลือกเชื่อมต่อผ่านส่วนขยาย ไม่ได้อ่านทุกแท็บอัตโนมัติ รักษาระบบอนุญาตและปุ่มหยุดเดิมไว้

## เปิดเว็บทดสอบ Caprii

**คลิกขวาตัวละคร → เปิดเว็บทดสอบ Caprii**

แอปจะเปิด server เฉพาะในเครื่องและเปิดหน้า Test Lab ใน browser ให้เอง ใช้ URL ที่แอปเปิดให้จริง พอร์ตอาจต่างจาก `5173` เมื่อปิด Caprii เว็บในเครื่องจะหยุดทำงาน

เลือกเคส → เชื่อมแท็บนั้นผ่านส่วนขยาย Caprii → คัดลอกคำสั่งไปบอก Caprii → ดูฟอร์มและ “หลักฐานของรอบนี้”

มี 8 เคส: อ่านข้อมูล, กรอกฟอร์ม, คำนวณ, ใช้แป้นบนช่อง readonly, รอผลช้าโดยไม่กดซ้ำ, อ่านช่องใหม่หลัง element เปลี่ยน กรอกโดยห้ามส่ง และอ่านรหัสจากรูปที่นำไปแนบในแชต ส่งออกรายงาน JSON เพื่อเก็บผลเทียบเวอร์ชันได้

ผลผ่านมาจากค่าช่องและเหตุการณ์บนหน้า เว็บยังแยกไม่ได้ว่าผู้ใช้หรือ Caprii เป็นผู้ลงมือ และไม่ยืนยันการบันทึกข้อมูลบน server ไม่มีการ publish เว็บทดสอบออนไลน์

ซอร์สเว็บและแนวทางอัปเดตพร้อม Caprii อยู่ที่ [Test Lab](https://github.com/Ternipitphon/my-finger-the-index/tree/caprii-0.7.6/caprii/test-lab)

## ความสามารถเดิมที่ยังอยู่

รวม Agent Reach 1.6.0 แบบ public-only พร้อม Python/dependencies ที่ล็อกเวอร์ชันและตรวจ checksum ใน Windows installer วางลิงก์เพื่ออ่านเว็บ ข้อมูลหรือคำบรรยาย YouTube และค้นข้อมูลผ่าน Jina/Exa/yt-dlp ไม่คัดลอกบัญชีหรือคุกกี้ ไม่ถอดเสียงแบบมีค่าใช้จ่าย ไม่อ้างว่าได้ดูคลิปจาก metadata และไม่ข้ามการปิดกั้นเครือข่าย

ยังมี Windows UI Automation, เครื่องมือเปิดไฟล์/โปรแกรม, การคำนวณพร้อมตรวจคำตอบ และการซ่อนหน้าติดตามงานตามการตั้งค่าเดิม ไม่เพิ่มความจำข้ามงานจากการอัปเดตนี้

## ทดสอบอะไรแล้ว

Chromium ใน environment ทดสอบนี้ถูกนโยบายผู้ดูแลบล็อกการโหลด unpacked extension จึงยังไม่ผ่านการทดสอบ popup/worker จริงใน Chromium ของรอบนี้ ใช้ unit tests และ authenticated broker/isolated DOM smoke ตรวจส่วนที่ทำได้ โดยไม่เปลี่ยนนโยบายหรืออ้างว่าเป็นผลบน Chrome/Windows จริง


ทดสอบหน้าต่าง Chat/Panel จริงเพิ่มเติม: แนบรูป, preview ก่อนส่ง, HTTP payload แบบหลายสื่อ, Ctrl+V ผ่าน ClipboardItem API, ส่งเฉพาะรูป, ถอดรูป, และแจ้งเมื่อโมเดลไม่รองรับภาพ รวมทั้งตรวจว่า history ไม่มีพิกเซลรูป


- **235 application tests ผ่าน** รวมวงจรเปิด/ปิด server ของ Test Lab และการตรวจเวอร์ชันแอป/lock/ส่วนขยายให้ตรงกัน
- **4 Test Lab unit/server checks ผ่าน**
- **8 เคส browser จริงผ่าน** พร้อมกรณีตอบผิด, readonly keypad, ผลตอบกลับช้า/รีเซ็ต, element เก่า, ห้ามส่ง, ตัวกรอง, รายงาน JSON และขนาดหน้าจอมือถือ
- ตรวจแพ็กเกจจริง: ASAR เวอร์ชัน 0.7.6, Windows x64 PE, Python ที่รวมไว้, ฟอนต์, ส่วนขยาย/DOM bridge และเปิด Test Lab จาก ASAR ได้
- ตรวจ archive ของ NSIS ผ่าน และรวม part กลับมาได้ SHA256 ตรงกับ installer

**ยังไม่ได้ลองติดตั้งและควบคุมบน Windows จริง** การ cross-build และการทดสอบบน Linux ไม่ยืนยันว่าการควบคุม Windows หรือทุกเว็บไซต์จะทำงานครบ ตัวติดตั้งยังไม่มีลายเซ็นดิจิทัล การอ่านเว็บจริงขึ้นกับเครือข่าย โควตา และข้อมูลที่เว็บไซต์เปิดให้ใช้
