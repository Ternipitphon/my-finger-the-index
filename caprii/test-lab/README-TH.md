Caprii 0.7.2 / suite 1.5.2: ทดสอบลากโดยปิดแชตใน companion fixture แยกจากคะแนน DOM ยังต้องตรวจเมาส์ Windows จริงหลังใช้ไปนาน ๆ

# Caprii Test Lab

เว็บทดสอบในเครื่องสำหรับ Caprii 0.5.9 โดยเริ่มจากซอร์ส commit `4413670984b7a3280d92f1dc1cbb31b8aaec82ff` ชุดทดสอบเวอร์ชัน 1.2.1 ไม่มีการ publish เว็บไซต์

## เปิดใช้

ถ้าติดตั้ง Caprii 0.5.9 แล้ว: คลิกขวาตัวละคร → **เปิดเว็บทดสอบ Caprii** แอปจะเปิด server ในเครื่องและ browser ให้เอง ไม่ต้องติดตั้ง Node.js แยก ปิด Caprii แล้ว server จะหยุด

สำหรับการเปิดซอร์สแยกจากแอป: ต้องมี Node.js 20 ขึ้นไป ไม่มี dependency ที่ต้องติดตั้ง

- Windows: แตกไฟล์แล้วเปิด `Start-Test-Lab.cmd`
- หรือเปิด terminal ในโฟลเดอร์นี้แล้วรัน `npm start`
- เปิด `http://127.0.0.1:5173` ใน Chrome เลือกเคส แล้วเชื่อมแท็บนี้กับส่วนขยาย Caprii จากนั้นคัดลอกคำสั่งไปบอก Caprii
- ดูสิ่งที่เกิดขึ้นบนฟอร์ม และผล DOM ใน “หลักฐานของรอบนี้” ควบคู่กัน
- เปลี่ยนเคสผ่านเมนูได้โดย URL ไม่เปลี่ยน หากรีโหลดหน้า/เปลี่ยน URL ให้เชื่อมแท็บใหม่
- เลือก “ส่งออกรายงาน” เพื่อดาวน์โหลด JSON หรือคัดลอกจากหน้าต่างรายงาน ผลอยู่ในหน่วยความจำของแท็บและหายเมื่อรีโหลด จึงควรเก็บรายงานก่อน

เปิด `dist/index.html` ได้โดยตรงเพื่อดูหน้า แต่ส่วนขยาย Caprii ต้องใช้ URL `http://` หรือ `https://` จึงควรเปิดผ่าน server ข้างต้น

## 8 เคสที่มี

อ่านข้อมูลจากบัตรร้านค้า, กรอกชื่อ/อีเมล/dropdown/checkbox, โจทย์คำนวณที่สุ่มใหม่เมื่อเริ่มเคส, ช่อง readonly กับแป้นบนเว็บ, รอเลขรับเรื่องใหม่ 1.5 วินาทีและไม่กดซ้ำ, สลับ element เพื่อทดสอบการอ่าน DOM ใหม่, กรอกโดยห้ามส่ง และภาพตัวอย่างสำหรับนำไปแนบในแชตแล้วตรวจรหัสที่อ่านได้

ทุกฟอร์มเป็นข้อมูลสมมติ ประมวลผลใน browser ไม่มี API ส่งข้อมูลออกภายนอก ใช้ฟอนต์ระบบและไฟล์ในชุดนี้ทั้งหมด ไม่ต้องเชื่อมต่ออินเทอร์เน็ตเพื่อใช้ Test Lab

## การตีความผล

“ผ่าน” หมายถึงค่าช่อง/เหตุการณ์บนหน้าเว็บตรงเงื่อนไข ไม่ใช่คำตอบของ AI ว่าทำสำเร็จ เว็บแยกไม่ได้ว่าผู้ใช้หรือ Caprii เป็นผู้ลงมือ จึงบันทึก actor เป็น `unknown-human-or-agent` ในรายงาน ไม่ยืนยันว่า AI ใช้ calculator tool จริง หรืออ่านค่ากลับด้วย tool ใด และไม่ยืนยันการบันทึก server หรือการควบคุม Windows

บางเคสกำหนดจำนวนส่งเป็นหนึ่งครั้ง ถ้ากดส่งผิดก่อนแล้วแก้ ให้กด “เริ่มเคสนี้ใหม่” เพื่อเริ่มนับใหม่ เคสรอผลจะยกเลิกผลลัพธ์เก่าถ้ามีการ reset ระหว่างรอ

## เมื่อพัฒนา Caprii ครั้งต่อไป

1. อัปเดต `dist/suite.js`: `capriiVersion`, `capriiCommit`, `version` และเพิ่ม case ID ใหม่ใน `cases` โดยรักษา ID เดิมสำหรับเปรียบเทียบย้อนหลัง
2. เพิ่มพื้นที่ทดสอบและเงื่อนไข DOM ที่สังเกตได้ใน `dist/app.js` โดยไม่ใส่ปุ่มกดผ่านเอง
3. เพิ่ม regression scenario ใน `tests/browser-smoke.cjs` และรัน `npm test` กับ `npm run test:browser` (ใช้ Electron จากโปรเจกต์ Caprii แม่)
4. อัปเดต README และบันทึกเวอร์ชันใน `CHANGELOG.md` ส่งซอร์สเว็บพร้อม Caprii บน branch เดียวกัน เว็บในเครื่องจะเปลี่ยนเมื่อดาวน์โหลด/ดึงซอร์สใหม่และเปิดใหม่ ไม่อัปเดตตัวเองเงียบ ๆ
5. ห้าม publish/deploy เว้นแต่ผู้ใช้อนุญาตสำหรับเว็บนี้

## ทดสอบสำหรับผู้พัฒนา

```sh
npm test
npm run test:browser
```

`test:browser` เปิด Electron กับ localhost ตรวจทั้ง UI และชุด DOM bridge ของ Caprii เมื่ออยู่ที่ `caprii/test-lab` โดยไม่เรียกโมเดล AI หรือเว็บไซต์ภายนอก การรันบน Linux ที่ไม่มีหน้าจออาจใช้ `electron --no-sandbox --ozone-platform=headless tests/browser-smoke.cjs` เฉพาะสภาพแวดล้อมทดสอบ

## บุคลิกและภาพใน 0.5.9

บุคลิกแนวรีเบคก้าเปิดเป็นค่าเริ่มต้น ปิดได้จากเมนูตัวละคร เลือกเคส “อ่านรูปที่แนบ” ดาวน์โหลดรูปแล้วแนบด้วย 📎 หรือ Ctrl+V ในแชต Caprii จากนั้นถามรหัสในภาพ แล้วนำคำตอบมาลงช่องทดสอบ เว็บตรวจได้เฉพาะรหัสที่ลงช่อง ไม่ยืนยันว่าโมเดลใช้ vision จริงหรือให้คะแนนบุคลิกอัตโนมัติ

## ตั้งค่าคำตอบใน 0.5.9

คลิกขวา Caprii → ความยาวคำตอบ / คำพูด เลือกสรุปสั้น สมดุล หรือละเอียด แล้วลองคำสั่งเดิมทั้งสามแบบและปิด–เปิดแอปเพื่อตรวจการจำค่า ทดสอบ “ข้อนี้ตอบอะไร” บนโจทย์โดยไม่สั่งกรอก คำตอบควรมาจากการอ่าน/คำนวณจริงและช่องต้องไม่เปลี่ยน ตัวเว็บไม่สามารถให้คะแนนความยาว คำตอบ AI หรือยืนยันการเลือกตั้งค่าเองได้ จึงยังคง 8 เคสที่มีหลักฐาน DOM สังเกตได้

## แก้คำสั่งใน 0.5.9

คำสั่งกรอกภาษาพูดของเคสเดิมและ “อ่านแท็บ…ยังไม่ต้องกรอกหรือกดส่ง” มี regression tests ที่ทางเข้า Chat จริง หากแท็บไม่เชื่อม แอปต้องแจ้งว่ายังไม่ได้ทำ งานอ่านค่าต้องอ้าง DOM และแสดงว่ายังไม่ได้กรอก/ส่ง ไม่ให้คะแนนจากคำพูดของโมเดล เคสเดิมทั้ง 8 คงไว้

ทดสอบ companion 0.6.0 เพิ่มเติม: ลากตัวละครระหว่างแอนิเมชันและปล่อยนอกตัวละคร; เปิดดูจอแล้วปิดก่อน AI ตอบ ต้องไม่มีบทพูดที่มาช้า; เลือก English แล้วคำตอบ/บทพูดดูจอเป็นอังกฤษ; ปิดและเปิดแอปใหม่เพื่อตรวจการจำค่า โจทย์ DOM เดิมยังครบ 8 เคส

0.6.1: ทดสอบคลิกติดแต่ไม่มี pointermove โดยใช้ MouseEvent อย่างเดียว, blur/lost mouse capture ระหว่างกดค้าง, native cursor fallback, คลิกขวา/คำสั่งยกเลิก และเมนูถาดระบบจับย้าย ไม่เปลี่ยนเกณฑ์ผ่านของ 8 เคส DOM

0.6.2: ตัวอย่างเปิดเว็บ Spotify และ example.org อยู่เหนือโจทย์เดิม ต้องตรวจหน้าต่างเบราว์เซอร์จริง ไม่มีปุ่มกดผ่านเองและไม่ให้คะแนน OS launch จาก DOM Test Lab

0.6.3: ทดสอบลากปกติและ Ctrl+Alt+M หลังใช้หลายรอบ เปรียบเทียบอาการคู่กัน การอ่านปุ่ม Windows และการลาก native ไม่ถูกรวมเป็นคะแนนผ่าน DOM สคริปต์ companion-smoke ทดสอบ 30 รอบด้วยสถานะปุ่มจำลอง

0.7.0: ตัวอย่าง YouTube และ Spotify อยู่เหนือโจทย์ รายงานแยก externalMedia=not-measured-by-this-page เพราะหน้า Test Lab ไม่เห็น browser ภายนอก รัน npm run test:media-ui เพื่อทดสอบ Spotify-shaped DOM fixture แบบไม่มีบัญชีจริง ไม่ได้พิสูจน์เสียงหรือ Spotify จริง

0.7.1: npm run test:media-transport ใช้ HTTP broker จริง รหัส fixture และ worker จำลองต่อกับ DOM จริงใน Electron ทดสอบการพัก heartbeat เกิน 8 วินาทีด้วยนาฬิกาจำลอง ปิดตัวจับเวลาใน isolated page และตรวจเวลาเพลงเดิน ไม่ใช่การทดสอบบัญชี Spotify/Chrome จริง
